# Agent 设计笔记：站在开源的肩膀上

这个项目的 Agent 不是凭空写的。我们把主流开源 Agent 与开源大模型
逐个拆开看过，把验证过的做法搬进来、把它们的坑绕开。这份笔记记录
**学了谁、学了什么、在代码哪里**，也记录不学的部分和理由。

一句话总纲（来自 SWE-bench 的反复教训）：同一个模型，换一套
harness（工具、提示、验证回路），成绩能差好几个百分点——
**"能不能用"一半在模型，一半在骨架。** 所以这个项目在骨架上花的
功夫不比选模型少。

## 参考与取舍

| 参考 | 学到的 | 落点 |
|---|---|---|
| **OpenHands**（65k★，自主软件工程师） | 事件驱动的 reason→act→observe 循环；工具结果即观察值回喂；靠迭代上限与**停滞检测**终止，而不是让模型自评成功 | `src/server.js` 的 chatTurn 事件流；连续失败 3 次注入系统提示要求换思路或汇报卡点 |
| **aider**（41k★，终端结对编程） | **RepoMap**：把代码库结构按相关性喂给模型，省掉探索轮次；编辑后自动 lint/测试、把报错回喂让模型自修（reflection 回路） | 每轮注入工作区**文件树**（`workspaceTree`）；Agent 协议第 4/5 条（必须真验证、出错就改） |
| **Cline**（IDE Agent） | **Plan 与 Act 分离**：先出计划再动手；长任务用可见清单跟踪；危险动作过人审 | 协议第 2 条（先说计划）；`update_tasks` 工具 + 聊天顶部任务清单条；审批卡（Allow / 本会话放行 / Deny） |
| **SWE-agent / Agentless 一系** | 骨架收敛于同一条脊柱：定位 → 读码 → 编辑 → 跑测试 → 读输出 → 迭代；测试反馈要**结构化**地回到模型 | 工具集形态（list/read/search/edit/shell）；shell 输出裁剪后回喂 |
| **smolagents**（HF） | CodeAgent 的洞察：让模型用**文本/代码表达动作**有时比死板的 JSON 工具调用更鲁棒，尤其对小模型 | 文本版工具调用拦截器 `parseTextToolCall`：小模型把 `{"name":…}` 当普通文本吐出来时，认出来真执行，不展示原文 |
| **LangGraph / 持久化 Agent 一系** | 长任务要**落盘的状态**，不能只活在上下文里：检查点、任务状态外置 | 任务清单按 bot 存盘（`data/tasks/<botId>.json`），跨轮次、跨重启可见 |
| **OpenMausBot / Grok Bot 一类产品** | 产品形态：聊天即界面、机器人名册、审批卡、团队即文件；但它的短板也明确：寄生他人 CLI 订阅、密钥明文存配置、"本地优先"只成立一半 | 形态学了（名册+聊天+PWA）；短板全反着做：自有引擎驱动层、密钥 AES-GCM 保险库、直连供应商无中转、本地模型可完全离线 |
| **DeepSeek**（模型与工程） | 开源权重一线水平 + 极低 API 价格；其模型对**格式明确的系统提示**响应极好，工具调用训练扎实 | 预设第一位；协议写成编号条款而非散文；`deepseek-chat` 直连无中介 |
| **Grok / xAI 开源部分**（Grok-1 权重等） | 产品层：聊天式 Agent 团队的交互范式（这也是用户最初的参照）；模型层为 MoE 路线的一家 | 交互形态参照；模型经 OpenRouter 可达即可，权重本地化优先级低于 Qwen/DeepSeek 系（部署成本与工具调用生态考量） |
| **Qwen3-Coder / Kimi K2 / GLM 系**（开源大模型） | Qwen：代码+工具调用双强、家族分档全（1.5B→480B）；Kimi：为长程 agentic 任务而生；GLM：长会话多步骤稳定性 | 预设与本地分档都按这三家的强项排：见下表 |

## 让结果"能用"的四件套（本项目落点）

1. **验证回路**（aider/OpenHands 的共识）：协议强制"写完必须真的跑起来
   验证"——`node --check`、起服务 curl、跑测试；没看到通过不许说完成。
   shell 超时从 30s 放宽到 120s，就是给构建与冒烟测试留的。
2. **交付物是部署包**：任务终点不是"代码写在聊天里"，而是
   `package_project` 打出的 zip（聊天里出下载卡片，聊天头 📦 也能
   手动打包）。能下载、能解压、能按 README 跑起来，才算交付。
3. **停滞熔断**：同一错误连犯 3 次，系统直接打断并要求换思路或
   向用户交代卡点——弱模型最常见的死法就是原地复读。
4. **上下文先行**：每轮把工作区文件树放在系统上下文里，模型起步
   就知道项目长什么样（RepoMap 的轻量版）。

## 模型分档（诚实版）

分数会过期，档位感不会。以下按"当 Agent 大脑"的实际体验排：

| 档 | 代表 | 定位 |
|---|---|---|
| 演示 | qwen2.5-coder:1.5b（本地） | 能聊天、能演示流程；真干活会犯傻（吐文本 JSON、不出声、幻觉路径），靠本项目的拦截与兜底才勉强像样 |
| 能用起步 | qwen2.5-coder:7b（本地）/ GLM-4.7-Flash（本地） | 简单多步任务可完成，工具调用基本规范 |
| 真干活（本地） | qwen3-coder:30b、qwen3.6:27b（本地，约 17-19 GB 内存） | 本地档的天花板附近：仓库级理解 + 可靠工具调用 |
| 真干活（API） | DeepSeek（deepseek-chat / reasoner）、Qwen3-Coder（DashScope）、Kimi K2.x、GLM 4.6+ | SWE-bench Verified 70% 上下的一线开源权重（厂商自报，harness 不同会有出入）；价格只有闭源前线的零头 |
| 旗舰 | Qwen3-Coder-480B、Kimi K2.5/2.6、DeepSeek V4-Pro、GLM-5.2（均经 API/OpenRouter） | 开源权重当前上限，长程任务与大仓库 |

经验法则：**内存/预算给到位时，模型升一档，比任何提示词技巧都管用；**
给不到时，靠本项目的验证回路与熔断兜底把下限抬住。
